# Security policy

## Supported development line

Security fixes are made on the latest `main` branch while the project is pre-release.

## Reporting a vulnerability

Until a private reporting channel is published, email the repository owner through the contact address shown on the GitHub profile. Include a minimal reproduction, impact, affected version/commit, and any suggested mitigation. Do not include real API keys, personal data, or publisher content that you do not have permission to share.

Please allow a reasonable time for acknowledgement and remediation before public disclosure. The project will credit reporters only with permission.

## Scope priorities

Secrets escaping the dashboard, owner-session bypasses, SSRF/custom-endpoint bypasses, unsafe feed parsing, unauthorized mutations, dependency supply-chain issues, and evidence/provenance integrity are high-priority reports.
